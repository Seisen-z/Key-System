# Reiya website administration
The unlisted URL and secret UUID are saved locally in `.admin-access.local` (ignored by Git and Vercel; Vite returns HTTP 403 for this file). No public navigation link. The route itself is not a security boundary and can be discovered in frontend assets. Actual data and actions require server authentication.

## Login and rotation
Login uses a separate cryptographically random UUIDv4 as a bearer credential, not a Supabase Auth user ID. Per request, this UUID is compared directly in the private database table as requested. Plaintext UUID storage is less resilient to database disclosure than hashing. Anyone who obtains it can sign in; keep it private.
Open Supabase Table Editor ? `reiya_admin_keys`. The Primary administrator row contains `login_uuid`. Replace it with a newly generated random UUIDv4 to rotate access, or set `enabled=false` to disable it. A database trigger invalidates existing sessions after either change. Save your new UUID separately; the local file is not automatically updated by Supabase edits. Do not choose a public or predictable UUID. More admins can be added as separate enabled rows.

## Controls
The latest 100 Premium subscriptions display the optional cloud display name, plan, access state, expiry, remaining days, registered devices and snapshot counts. This is not Roblox credential analytics. Free local users are not tracked.
Premium keys are masked by default, revealed only via an authorized, audited server action. They grant access to the user's Premium cloud profile, so treat them as credentials. No backup contents, Roblox passwords/cookies or encryption master keys are exposed.
Add/remove whole days (max 3650 per change), or enable/disable a key. A reason is mandatory and recorded. UUID-like identifiers and Premium keys are redacted from reasons. Changes modify access, not PayPal billing. Future payment/receipt events may overwrite manually edited access expiry; no change is a refund or cancellation. Disabling an access key revokes Premium sessions. Enabling a still-expired key alone does not extend its expiry.

## Security and verification
Admin UUID table, hashed-session table, audit table and RPCs deny anon/authenticated access; only the server service role can call them. UUID login rate limit is 5 attempts per IP per 15 minutes; views/changes have separate limits. Sessions last 20 minutes and tokens stay only in frontend memory. No persistence or URL tokens. API rejects untrusted POST origins, oversized bodies and unauthenticated actions. Responses use no-store. No code is reverse-engineering-proof; security relies on server checks.
The migration was applied to the existing Supabase project. No deployment or app changes. Source rollback retains database tables/audit records; set enabled=false in Supabase if disabling this feature. No real subscriber access changes were performed during testing. SQL fixture tests were rolled back.

## Change the admin website URL in Supabase
Open Table Editor ? reiya_admin_settings ? row key=admin_path. Edit value from /admin23292 to another unique single-segment path, for example /admin-21032. Use http://localhost:5173 followed by the new value for local testing; use your website origin after an explicit deployment. The path must be 3?80 letters/numbers/hyphens/underscores after the leading slash and must not collide with public routes. Changes take effect on the next route lookup without rebuilding. A trigger invalidates all admin sessions when the value changes; the old URL resolves to Page not found and old-page login is rejected. Your UUID remains unchanged. The local .admin-access.local bookmark is not automatically rewritten by a database edit; update it manually if wanted. Unknown-route lookups are rate-limited and return only a match boolean, not the configured path. The unlisted URL is not an authentication credential.
